# 天锋发布工程

先从本 Skill 的真实路径向上查找 `scripts/manage.py`，其上级就是项目根目录。工程放在根目录的 `发布工程/系列/期数/`。写入前检查项目所在磁盘已连接并可写。

## 素材与工程

1. 先复用用户已确认的成片、封面、文案与平台范围；与天锋口播 Skill 衔接，不重新改写已定稿内容。缺少成片时只整理可完成部分，说明缺失，不能用演示媒体冒充。
2. 用户未另行更改时，作品描述约15字、绝不超过30字；内容简介60—100字；抖音、小红书、视频号各5个相关话题。另遵守各平台实际字段上限：小红书标题20字，视频号短标题6—16字。以上不是自动增添平台的授权。
3. 将实际使用的文件复制到当期工程，保留原件并核对哈希：`成片.mp4`、`发布素材.md`、`封面/cover-3x4.png`、`封面/cover-4x3.png`，可选 `字幕.srt`。只有当前平台需要时才准备16:9衍生封面。
4. 按 [发布素材格式](references/发布素材格式.md) 适配解析格式，不改变文案含义。缺少某平台时不要增加对应章节。成片需 faststart；若校验提示封装问题，在项目内另存修正版并验证，不覆盖原件。
5. 在项目根目录运行下面命令。启动器负责 Node 路径和本机配置，不读取或输出真实口令。

```bash
python3 scripts/manage.py tool make-publish.mjs "发布素材.md的完整路径" "当期工程的完整路径"
python3 scripts/manage.py tool validate.mjs "当期工程的完整路径"
```

校验错误必须处理；不要用虚构素材或删掉用户要求绕过错误。警告结合实际需求解释；保留用户明确要求的文字，不自动把上游的一般写法当成新要求。

## 排期与平台操作

本地整理、校验不代表用户授权上传或发布。登记排期、上传填写、发布或通知他人，按用户本轮及有效历史中的明确授权执行；若已授权就不要重复询问。

```bash
python3 scripts/manage.py hub plan "当期工程的完整路径"
python3 scripts/manage.py hub status
python3 scripts/manage.py hub run "当期工程的完整路径"
```

`plan` 会登记分发计划；自动守护进程开启后可能执行已登记计划，因此只在用户已指定平台和时间并要求排期时使用。`run` 会上传和填写，须有相应授权。当前部署所有平台均为人工最终提交，抖音、小红书、视频号最后的发布按钮交给用户。

账号由用户在专用 Chrome 登录；使用项目 `02_登录平台账号.command` 和 `03_检查账号状态.command`。不索要平台密码、Cookie或本机访问口令。失败重跑先核对平台记录，避免重复上传/发帖。没有用户要求时不启用守护进程、不改自动提交配置、不发通知。

交付时给出工程入口、各平台文案、校验结论及当前真实状态；明确区分“素材已备好”“已填写”“用户已发布”。
